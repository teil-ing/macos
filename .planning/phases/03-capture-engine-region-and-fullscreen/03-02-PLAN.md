  <name>Task 1: SelectionOverlayView — dimming, crosshair, marching ants, dimension label, mouse tracking</name>
  <files>
    teil.ing-client/Views/SelectionOverlayView.swift
  </files>
  <action>
    Create `SelectionOverlayView: NSView` — the content view for each overlay window. This view handles ALL drawing and mouse interaction for region selection on one display.

    **Layer setup (in init or viewDidMoveToWindow):**
    - Set `wantsLayer = true`.
    - Create a `dimmingLayer: CALayer` covering the full bounds with `backgroundColor = NSColor.black.withAlphaComponent(0.3).cgColor` (Claude's discretion on exact opacity — 0.3 is a good macOS-native feel).
    - Create a `selectionLayer: CAShapeLayer` for the marching-ants selection border:
      - `strokeColor = NSColor.white.cgColor`, `fillColor = NSColor.clear.cgColor`
      - `lineWidth = 1.5`, `lineDashPattern = [6, 4]`
      - Add `CABasicAnimation(keyPath: "lineDashPhase")` from 0 to -(6+4), duration 0.5, repeatCount .infinity.
      - Initially hidden (no path set).
    - Create `guideHorizontalLayer: CAShapeLayer` and `guideVerticalLayer: CAShapeLayer` for crosshair lines:
      - `strokeColor = NSColor.white.withAlphaComponent(0.4).cgColor`, `lineWidth = 0.5`
      - These span the entire view width (horizontal) or height (vertical), updating as mouse moves.
    - Create `dimensionLabel: NSTextField` (or use a `CATextLayer`):
      - Non-editable, non-selectable label showing "W x H" pixel dimensions.
      - Style: `.monospacedDigitSystemFont(ofSize: 12, weight: .medium)`, white text on a dark semi-transparent rounded background pill.
      - Use an NSTextField with `.backgroundColor = NSColor.black.withAlphaComponent(0.7)`, rounded corners via layer, or a small NSVisualEffectView.
      - Position: offset ~20pt below and to the right of the selection's bottom-right corner. If that would go off-screen, reposition above or to the left.
      - Initially hidden.

    **Dimming with selection cutout:**
    - When a selection rect exists, use a `CAShapeLayer` as the dimming layer's mask (or use the dimmingLayer path approach):
      - Create a path that covers the full bounds, then add the selection rect as a subpath with `.evenOdd` fill rule. This makes the selection area clear (not dimmed) while the rest is dimmed.
      - Alternative: use a separate clearRect approach by setting the dimmingLayer as a CAShapeLayer with evenOdd fill.

    **Mouse tracking (mouseDown override):**
    - Override `mouseDown(with:)`.
    - Record `startPoint = convert(event.locationInWindow, from: nil)` — in view coordinates.
    - Enter tracking loop: `while let next = window?.nextEvent(matching: [.leftMouseDragged, .leftMouseUp, .rightMouseDown, .keyDown])`:
      - `.leftMouseDragged`: compute current point, update selection rect (normalize for negative drag directions), update all layers (dimming cutout, selection border path, guide lines, dimension label).
      - `.leftMouseUp`: compute final rect. If width >= 10 AND height >= 10 (in backing pixels: multiply by window's backingScaleFactor), this is a valid selection. Convert to screen coordinates using `window?.convertPoint(toScreen:)`. Store result and break loop. If < 10x10, treat as cancel.
      - `.rightMouseDown` or `.keyDown` where keyCode == 53 (Escape): cancel — break loop with nil result.
    - After loop: call a completion handler or set a result property that OverlayCoordinator reads.

    **Guide line updates during drag:**
    - `guideHorizontalLayer.path` = horizontal line at current mouse Y position, spanning full view width.
    - `guideVerticalLayer.path` = vertical line at current mouse X position, spanning full view height.
    - Update these on every mouseMoved AND mouseDragged event.

    **Pre-drag crosshair (before mouseDown):**
    - Override `mouseMoved(with:)` to update guide line positions as the cursor moves over the overlay (before any click).
    - Set `self.acceptsFirstResponder = true` and override to return `true`.
    - The window needs `acceptsMouseMovedEvents = true` (set by OverlayCoordinator).

    **Cursor management:**
    - Override `resetCursorRects()` and call `addCursorRect(bounds, cursor: .crosshair)`.
    - Or use `NSCursor.crosshair.push()` in OverlayCoordinator when showing overlay, `.pop()` when done.

    **Coordinate conversion notes:**
    - View coordinates: origin at bottom-left of the view (which matches the window/screen origin in AppKit).
    - To convert to screen coordinates: `window?.convertPoint(toScreen: viewPoint)`.
    - The dimension label should show dimensions in backing pixels: `Int(rect.width * backingScaleFactor) x Int(rect.height * backingScaleFactor)`.

    **Properties to expose:**
    - `var selectionResult: CGRect?` — the final selection in global screen coordinates, nil if cancelled.
    - `var onSelectionComplete: ((CGRect?) -> Void)?` — callback for when selection finishes.
    - `var owningScreen: NSScreen?` — which screen this view's window covers (needed for coordinate conversion).

  <name>Task 2: OverlayCoordinator — multi-monitor window management and selection lifecycle</name>
  <files>
    teil.ing-client/Services/OverlayCoordinator.swift
  </files>
  <action>
    Create `@MainActor final class OverlayCoordinator` — manages the lifecycle of overlay windows across all connected displays and returns the user's selection result.

    **Public API:**
    - `func beginRegionSelection() async -> CGRect?` — shows overlays on all screens, waits for user to complete or cancel selection, tears down overlays, returns global CGRect or nil.

    **Window creation (private):**
    - `private func createOverlayWindows() -> [(NSWindow, SelectionOverlayView)]`:
      - For each `NSScreen.screens`, create an `NSWindow`:
        - `contentRect: screen.frame` (full screen coverage)
        - `styleMask: [.borderless]`
        - `backing: .buffered`, `defer: false`, `screen: screen`
        - `window.level = .screenSaver` (above all normal windows including fullscreen apps)
        - `window.backgroundColor = .clear`
        - `window.isOpaque = false`
        - `window.hasShadow = false`
        - `window.ignoresMouseEvents = false`
        - `window.collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]`
        - `window.isReleasedWhenClosed = false`
        - `window.acceptsMouseMovedEvents = true`
        - `window.sharingType = .none` (exclude from SCK capture on macOS 13/14; macOS 15 ignores this but SCContentFilter exclusion handles it)
      - Create `SelectionOverlayView(frame: screen.frame)` and set as `window.contentView`.
      - Set `view.owningScreen = screen`.
      - Return array of (window, view) pairs.

    **Selection lifecycle:**
    - In `beginRegionSelection()`:
      1. Create overlay windows for all screens.
      2. Push crosshair cursor: `NSCursor.crosshair.push()`.
      3. Order all windows front: `window.orderFrontRegardless()`.
      4. Make the window on the active screen (where cursor is) the key window: find which screen contains `NSEvent.mouseLocation`, make that window `makeKey()`.
      5. Use `withCheckedContinuation` to bridge the callback-based selection result to async/await. Set the `onSelectionComplete` callback on all SelectionOverlayView instances. The first view to produce a result (selection or cancel) resumes the continuation.
      6. When result received: pop cursor (`NSCursor.pop()`), order out all windows, close them.
      7. Return the CGRect (valid selection) or nil (cancelled).

    **Multi-monitor drag handling:**
    - The user can start dragging on monitor A and continue onto monitor B. Since each monitor has its own NSWindow, the mouse events are delivered to the window under the cursor.
    - Approach: When the user starts dragging on one overlay view, that view "owns" the drag via its `nextEvent` tracking loop. The `nextEvent` call on the window will continue to receive events even as the mouse moves to another screen (AppKit delivers dragged events to the window that received mouseDown).
    - The start point is in the original window's screen coordinates. The end point may be in a different screen's coordinate space. Convert both to global screen coordinates for the final rect.
    - The selection visual (marching ants, dimming cutout) only renders on the window that owns the drag. This is acceptable — the user sees the selection on the origin screen. (For cross-monitor visual, we would need to synchronize drawing across windows, but this adds complexity. The capture itself will correctly span both monitors via CaptureEngine's multi-display logic.)

    **Cleanup:**
    - Always clean up (pop cursor, close windows) even on cancel.
    - Store window references in a property to prevent ARC deallocation during the selection.
    - Set `isReleasedWhenClosed = false` on windows to prevent premature release.

    **Important Swift 6 notes:**
    - This class is `@MainActor` — all NSWindow/NSView operations must be on main thread.
    - The `withCheckedContinuation` callback from SelectionOverlayView must be dispatched to MainActor context.
    - SelectionOverlayView's `onSelectionComplete` closure captures `@MainActor`-isolated state — mark the closure as `@MainActor @Sendable` or ensure it's called on the main thread (it will be, since mouse events are main thread).
  </action>
