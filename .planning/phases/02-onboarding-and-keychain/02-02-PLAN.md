**OnboardingViewModel.swift:**

Create `@MainActor final class OnboardingViewModel: ObservableObject`.

Published state:
- `@Published var apiKey: String = ""` — bound to the text field
- `@Published var isRevealed: Bool = false` — toggles SecureField vs TextField
- `@Published var isValidating: Bool = false` — shows inline spinner
- `@Published var errorMessage: String? = nil` — inline red error text below field
- `@Published var shakeAttempts: Int = 0` — incremented to trigger shake animation
- `@Published var phase: OnboardingPhase = .apiKey` — tracks which section of the single-screen view is active

Define `enum OnboardingPhase` with cases: `.apiKey` (initial), `.screenRecording` (after key saved), `.complete`.

Callback: `var onComplete: (() -> Void)?` — called when onboarding finishes successfully.

Method `func validateAndSave() async`:
1. Trim whitespace from `apiKey`. If empty, set `errorMessage = "Please enter your API key."`, increment `shakeAttempts` with `withAnimation(.default)`, return.
2. Set `isValidating = true`, clear `errorMessage`. Defer `isValidating = false`.
3. Call `await APIValidationService.validate(apiKey: trimmedKey)`.
4. Switch on result:
   - `.valid`: Call `try KeychainService.shared.save(trimmedKey)`. On success, set `phase = .screenRecording`. On KeychainError, set `errorMessage = "Could not save API key to Keychain: \(error.localizedDescription)"`.
   - `.invalidKey`: Set `errorMessage = "Invalid API key. Please check and try again."`, increment `shakeAttempts` with `withAnimation(.default)`.
   - `.networkError(let message)`: Set `errorMessage = message` (already user-friendly from the service).
   - `.serverError(let code)`: Set `errorMessage = "Unexpected server response (\(code)). Try again later."`, increment `shakeAttempts` with `withAnimation(.default)`.

Method `func checkPermission() async`:
1. Call `await PermissionService.checkScreenRecordingPermission()`.
2. If `true`: set `phase = .complete`, then call `onComplete?()`.
3. If `false`: Do nothing — the user needs to grant permission in System Settings and tap the "I've granted permission" button to re-check.

Method `func openSettings()`:
1. Call `PermissionService.openScreenRecordingSettings()`.

Method `func retryPermissionCheck() async`:
1. Same as `checkPermission()` — called by the "I've granted permission — continue" button.

**OnboardingView.swift:**

**API key section (visible when `viewModel.phase == .apiKey`):**
- SecureField / TextField toggle (per locked decision — masked by default with reveal toggle):
  - `HStack` containing:
    - `Group` switching between `SecureField("Paste your API key", text: $viewModel.apiKey)` and `TextField("Paste your API key", text: $viewModel.apiKey)` based on `viewModel.isRevealed`
    - Both use `.textFieldStyle(.roundedBorder)` and share a `@FocusState`
    - Eye toggle button: `Button` with `Image(systemName: viewModel.isRevealed ? "eye.slash" : "eye")`, `.buttonStyle(.plain)`, `.foregroundStyle(.secondary)`
    - Inline spinner: `if viewModel.isValidating { ProgressView().progressViewStyle(.circular).controlSize(.small) }`

**Screen Recording section (visible when `viewModel.phase == .screenRecording`):**
- Explanation text: "teil.ing needs Screen Recording permission to capture screenshots. This allows the app to take screenshots of your screen when you trigger a capture." in `.body` font, `.multilineTextAlignment(.center)`.
- "Open System Settings" button: `.buttonStyle(.borderedProminent)`, calls `viewModel.openSettings()`.
- "I've granted permission — continue" button: `.buttonStyle(.bordered)`, calls `Task { await viewModel.retryPermissionCheck() }`.
- Note: The first time this section appears, automatically call `Task { await viewModel.checkPermission() }` via `.onAppear` on this section — this triggers the TCC prompt. If permission is already granted (e.g., from a previous app install), it skips straight to complete.

Modify `AppDelegate.swift` to add launch-time onboarding routing.

**New property:**
- `private var onboardingWindowController: OnboardingWindowController?`

**Modify `applicationDidFinishLaunching`:**
Replace the current body with:
1. `NSApp.setActivationPolicy(.accessory)` (keep existing belt-and-suspenders).
2. Check `KeychainService.shared.apiKey`:
   - If `nil` → call `showOnboardingWindow()` (first launch — no key found).
   - If non-nil → call `showWelcomeBackAndProceed()` (returning user — key found in Keychain).

**New method `private func showOnboardingWindow()`:**
1. Switch activation policy: `NSApp.setActivationPolicy(.regular)` — required for the window to become key (per research pitfall 1).
2. Create `OnboardingWindowController()`.
3. Set `controller.onComplete = { [weak self] in ... }`:
   - Inside the callback: set `self?.onboardingWindowController = nil` (release the controller).
   - Call `NSApp.setActivationPolicy(.accessory)` to restore menu-bar-only mode.
   - Call `self?.completeLaunch()` to set up the status item and popover.
4. Call `controller.showWindow(nil)`, `controller.window?.center()`, `controller.window?.makeKeyAndOrderFront(nil)`, `NSApp.activate(ignoringOtherApps: true)`.
5. Retain: `onboardingWindowController = controller`.

**New method `private func showWelcomeBackAndProceed()`:**
Per locked decision: show brief "Welcome back — API key found" confirmation, then proceed to main UI.
1. Switch to `.regular` temporarily so the toast window can show.
2. Create a small NSWindow (or NSPanel) ~300x120pt, centered, with `.titled` style, no close button needed.
3. Host a simple SwiftUI view: VStack with `Image(nsImage: NSApp.applicationIconImage)` at 32pt, `Text("Welcome back!")` in `.headline`, `Text("API key found — launching...")` in `.subheadline .secondary`.
4. Show the window centered.
5. After 1.5 seconds (`Task.sleep(for: .milliseconds(1500))`), close the window, switch back to `.accessory`, and call `completeLaunch()`.

Alternative simpler approach if the separate window feels over-engineered: skip the welcome-back window and just call `completeLaunch()` directly. Use Claude's discretion here — the user said "brief confirmation" which could be a transient window or could be the popover itself showing a welcome message. A small standalone window for 1.5 seconds is clean and matches the user's intent.

**New method `private func completeLaunch()`:**
Factor the existing `setupStatusItem()` and `setupPopover()` calls into this shared method:
```swift
private func completeLaunch() {
    setupStatusItem()
    setupPopover()
}
```

Both the onboarding-complete path and the returning-user path call `completeLaunch()`.

**Do NOT remove** the existing `setupStatusItem()`, `setupPopover()`, `togglePopover()`, `showPopover()`, `closePopover()`, `startEventMonitor()`, `stopEventMonitor()` methods — they stay as-is. Only the `applicationDidFinishLaunching` body changes, and the new methods are added.

**Do NOT call `setupStatusItem()` or `setupPopover()` directly from `applicationDidFinishLaunching` anymore** — both paths go through the onboarding gate first.
