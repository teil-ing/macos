    **AppDelegate.swift — capture trigger flow:**
    - Add stored properties:
      - `private let captureEngine = CaptureEngine()`
      - `private let overlayCoordinator = OverlayCoordinator()`
      - `private var lastCaptureResult: CaptureResult?` (for future use by upload pipeline)
    - Update `setupPopover()`: create PopoverRootView with action closures wired:
      ```swift
      let rootView = PopoverRootView(
          onRegionCapture: { [weak self] in self?.startRegionCapture() },
          onFullscreenCapture: { [weak self] in self?.startFullscreenCapture() }
      )
      ```
    - `private func startRegionCapture()`:
      1. `closePopover()` — dismiss the popover first.
      2. `Task { @MainActor in ... }`:
         a. `try? await Task.sleep(for: .milliseconds(200))` — let popover fully dismiss (per locked decision).
         b. `guard let selectedRect = await overlayCoordinator.beginRegionSelection() else { return }` — show overlay, wait for selection. If nil (cancelled), return.
         c. Hide overlay windows, wait one compositor frame: `try? await Task.sleep(for: .milliseconds(50))`.
         d. `let result = try await captureEngine.captureRegion(selectedRect)`.
         e. `self.lastCaptureResult = result`.
         f. `await CaptureFeedback.showCaptureFlash(in: selectedRect)` — flash on captured area.
         g. `CaptureFeedback.playCaptureSound()`.
         h. `CaptureFeedback.showSuccessIcon(on: self.statusItem)` — briefly change menu bar icon.
      3. Wrap in do/catch: on error, show error in popover (reopen popover, show alert message).
    - `private func startFullscreenCapture()`:
      1. `closePopover()`.
      2. `Task { @MainActor in ... }`:
         a. `try? await Task.sleep(for: .milliseconds(200))` — let popover dismiss (per locked decision: fullscreen fires instantly after popover dismiss, but we still need the 200ms for the popover to clear).
         b. `let result = try await captureEngine.captureFullscreen()`.
         c. `self.lastCaptureResult = result`.
         d. `await CaptureFeedback.showCaptureFlash(in: result.capturedRect)`.
         e. `CaptureFeedback.playCaptureSound()`.
         f. `CaptureFeedback.showSuccessIcon(on: self.statusItem)`.
      3. Wrap in do/catch: on error, show error in popover.
    - Error display: On capture error, reopen the popover and show the error message. For now, use a simple approach: store an `@Published` error string that PopoverRootView can display, or use a separate error banner view. A simple approach: add `private var captureError: String?` and when set, reopen the popover. In PopoverRootView, show a red Text banner if error is non-nil. The exact error UI mechanism is flexible — the key requirement is that errors appear inside the popover per locked decision.

    **Important notes:**
    - The 50ms sleep after hiding overlay (before capture call) ensures the overlay is fully off-screen and not captured. The OverlayCoordinator handles orderOut inside beginRegionSelection before returning, but adding the small delay ensures the compositor has cleared the overlay.
    - `captureEngine` is an actor, so calls are already async-safe.
    - After successful capture, popover stays CLOSED — only the menu bar icon shows success (per locked decision).

<task type="auto">
  <name>Task 2: CaptureFeedback — flash window, system sound, and menu bar icon success state</name>
  <files>
    teil.ing-client/Services/CaptureFeedback.swift

  <action>
    Create `@MainActor enum CaptureFeedback` (caseless enum namespace, @MainActor since it manipulates NSWindows and NSStatusItem).

    **showCaptureFlash(in rect: CGRect):**
    - Find which NSScreen contains the rect (or the largest portion of it).
    - Create a borderless NSWindow at `rect` position:
      - `styleMask: [.borderless]`, `backing: .buffered`
      - `window.level = .screenSaver` (above everything)
      - `window.backgroundColor = .white`
      - `window.isOpaque = true`
      - `window.alphaValue = 0.8` (Claude's discretion — bright but not blinding)
      - `window.isReleasedWhenClosed = false`
    - `window.orderFront(nil)`.
    - Animate fade-out using `NSAnimationContext.runAnimationGroup`:
      - `ctx.duration = 0.15` (quick flash)
      - `window.animator().alphaValue = 0.0`
      - In completionHandler: `window.orderOut(nil)`.
    - Use `withCheckedContinuation` to make this awaitable (resume in the completion handler) so the caller can await the flash before proceeding. Or use `async` with `Task.sleep` after triggering. Either approach works — the flash is fire-and-forget visually but nice to await for sequencing.

    **playCaptureSound():**
    - `import AudioToolbox`
    - Try system sound first: `AudioServicesPlaySystemSound(1108)` (camera shutter sound ID).
    - No fallback needed — if the sound ID doesn't work on some macOS version, silence is acceptable. The research notes this is MEDIUM confidence but acceptable.
    - Alternative: `NSSound(named: "Glass")?.play()` or `NSSound(named: "Tink")?.play()` as a safer cross-version option. Claude's discretion on which approach.

    **showSuccessIcon(on statusItem: NSStatusItem):**
    - Change the status item's button image to a success indicator:
      - `let successImage = NSImage(systemSymbolName: "checkmark.circle.fill", accessibilityDescription: "Capture successful")`
      - `successImage?.isTemplate = true`
      - `statusItem.button?.image = successImage`
    - After ~2 seconds, revert to the normal icon:
      - `Task { try? await Task.sleep(for: .seconds(2)); self.restoreNormalIcon(on: statusItem) }`
      - `restoreNormalIcon`: sets image back to `NSImage(systemSymbolName: "rectangle.dashed", accessibilityDescription: "teil.ing")` with `isTemplate = true`.
    - Guard against rapid successive captures: if a new capture starts while the success icon is showing, the revert task should be cancelled. Use a stored `Task` reference and cancel it before setting new success icon.

    **Important notes:**
    - All NSWindow and NSStatusItem manipulation must be on MainActor (guaranteed by the @MainActor enum).
    - The flash window should not interfere with the capture — it appears AFTER the capture is complete.
    - The status item icon change is per the locked decision: "Menu bar icon briefly changes to a success indicator (checkmark/green) for ~2 seconds, then reverts to normal."
  </action>
