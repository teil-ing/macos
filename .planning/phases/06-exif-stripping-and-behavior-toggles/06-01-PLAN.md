**1. Create `teil.ing-client/Services/PreferencesStore.swift`:**

Create a new file with a `@MainActor final class PreferencesStore: ObservableObject` singleton.

Three `@AppStorage` properties — all defaulting to `true`:
- `@AppStorage("pref_stripExif") var stripExif: Bool = true` — strip EXIF metadata server-side
- `@AppStorage("pref_openInBrowser") var openInBrowser: Bool = true` — open share URL in browser after upload
- `@AppStorage("pref_clipboardCopy") var clipboardCopy: Bool = true` — copy share URL to clipboard after upload

Use `static let shared = PreferencesStore()` with `private init()` — matches existing singleton pattern (UploadService.shared, KeychainService.shared).

Import `SwiftUI` (required for @AppStorage). Do NOT use `@Observable` macro — it is incompatible with @AppStorage (research Pitfall 1). Use `pref_` prefix for all UserDefaults keys to avoid collision with KeyboardShortcuts library (research Pitfall 3).

**2. Update `UploadService.swift` — `enqueue()` signature:**

Add three Bool parameters after `capture`:
```
func enqueue(
    _ capture: CaptureResult,
    stripExif: Bool,
    openInBrowser: Bool,
    clipboardCopy: Bool,
    onFeedback: @MainActor @Sendable @escaping (UploadFeedbackEvent) -> Void
)
```

Inside enqueue, snapshot the three values into local `let` constants (just like `capturedPendingCount`):
```
let capturedStripExif = stripExif
let capturedOpenInBrowser = openInBrowser
let capturedClipboardCopy = clipboardCopy
```

Pass all three to `performUpload()`.

**3. Update `UploadService.swift` — `retry()` signature:**

Add the same three Bool parameters:
```
func retry(
    stripExif: Bool,
    openInBrowser: Bool,
    clipboardCopy: Bool,
    onFeedback: @MainActor @Sendable @escaping (UploadFeedbackEvent) -> Void
)
```

Forward them to `enqueue()`.

**4. Update `UploadService.swift` — `performUpload()` signature:**

Add `stripExif: Bool`, `openInBrowser: Bool`, `clipboardCopy: Bool` parameters. Update the chained Task in `enqueue()` to pass them through.

**5. Update `UploadService.swift` — `buildMultipartRequest()` signature:**

Add `stripExif: Bool` parameter. When `stripExif == true`, append the form field BEFORE the closing boundary:
```swift
if stripExif {
    body.append("--\(boundary)\r\n")
    body.append("Content-Disposition: form-data; name=\"stripExif\"\r\n")
    body.append("\r\n")
    body.append("true")
    body.append("\r\n")
}
```

When `stripExif == false`, do NOT append the field at all. Do NOT send `stripExif=false` — the API contract specifies omission means no stripping.

Update the call site in `performUpload()` to pass `stripExif`.

**6. Update `UploadService.swift` — post-upload action gates in `performUpload()`:**

Replace the existing unconditional clipboard/browser block:
```swift
let isLast = capturedPendingCount == pendingCount
if isLast {
    await copyToClipboard(result.shareUrl)
    await openInBrowser(result.shareUrl)
}
```

With preference-gated version:
```swift
let isLast = capturedPendingCount == pendingCount
if isLast {
    if capturedClipboardCopy {
        await copyToClipboard(result.shareUrl)
    }
    if capturedOpenInBrowser {
        await openInBrowser(result.shareUrl)
    }
}
```

The `isLast` guard is preserved — preferences are an additional gate, not a replacement for last-wins logic.
