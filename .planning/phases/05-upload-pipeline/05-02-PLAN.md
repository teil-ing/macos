  <action>
Extend the existing `CaptureFeedback` enum with three new static methods. Add `import QuartzCore` at the top (for CABasicAnimation, CAMediaTimingFunction).

**1. `showUploadSpinner(on statusItem: NSStatusItem)`:**
- Cancel any pending `iconRevertTask` (a spinner supersedes a pending success revert)
- Set `button.image` to `NSImage(systemSymbolName: "arrow.triangle.2.circlepath", accessibilityDescription: "Uploading")` with `isTemplate = true`
- Set `button.wantsLayer = true` (required for CABasicAnimation — AppKit views don't have layers by default)
- Create a `CABasicAnimation(keyPath: "transform.rotation.z")`:
  - `toValue`: `CGFloat.pi * 2`
  - `duration`: `1.0`
  - `timingFunction`: `CAMediaTimingFunction(name: .linear)`
  - `repeatCount`: `.infinity`
- Add the animation to `button.layer` with key `"uploadSpinner"`

**2. `stopUploadSpinner(on statusItem: NSStatusItem)`:**
- Remove the animation from `button.layer` with key `"uploadSpinner"`
- This does NOT change the image — the caller decides what icon to show next (success checkmark or error icon)

**3. `showErrorIcon(on statusItem: NSStatusItem)`:**
- Call `stopUploadSpinner(on: statusItem)` first (belt-and-suspenders)
- Cancel any pending `iconRevertTask`
- Set `button.image` to `NSImage(systemSymbolName: "exclamationmark.triangle.fill", accessibilityDescription: "Upload failed")` with `isTemplate = true`
- Do NOT auto-revert — the error icon stays until the user opens the popover (AppDelegate handles clearing it)

**4. `restoreNormalIcon(on statusItem: NSStatusItem)` — make this `internal` (remove `private`):**
- Change from `private` to `static func` (no access modifier = internal). Plan 03 needs AppDelegate to call this when the user dismisses the error or a retry succeeds.

All methods are already `@MainActor` via the enum declaration. No new properties needed beyond the existing `iconRevertTask`.

  <action>
Modify `PopoverRootView` to accept two new optional parameters for upload errors:

**New properties:**
- `var uploadError: String?` — non-nil when the most recent upload failed after all retries
- `var onRetry: (() -> Void)?` — called when the user taps Retry

**Upload error banner (add ABOVE the existing `captureError` banner, or below it — they should not conflict since they represent different error states):**

Place the upload error banner right after `VStack(spacing: 0) {` and before the capture error check:

```swift
if let uploadError = uploadError {
    VStack(spacing: 6) {
        HStack(spacing: 6) {
            Image(systemName: "exclamationmark.triangle.fill")
                .foregroundStyle(.red)
            Text(uploadError)
                .font(.caption)
                .foregroundStyle(.red)
                .lineLimit(2)
            Spacer()
        }
        if onRetry != nil {
            Button {
                onRetry?()
            } label: {
                Text("Retry Upload")
                    .font(.caption)
                    .frame(maxWidth: .infinity)
            }
            .controlSize(.small)
        }
    }
    .padding(.horizontal, 12)
    .padding(.vertical, 8)
    .background(Color.red.opacity(0.08))

    Divider()
}
```

The styling matches the existing `captureError` banner pattern (same padding, same red.opacity(0.08) background, same font sizes) — per locked decision, error UI uses the popover's existing design system.

**Important:** Keep all existing properties and functionality. The `captureError` banner continues to work for capture-time errors. Upload errors are a separate concern with a Retry button (capture errors do not have Retry).

Update the `#Preview` to show both states for development:
```swift
#Preview("Upload Error") {
    PopoverRootView(uploadError: "API key is invalid or expired.", onRetry: {})
}
```
