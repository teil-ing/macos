## Decisions Made

- **File-scope Name extensions:** KeyboardShortcuts.Name extensions defined at file scope (outside any type) for Swift 6 strict concurrency compliance — nested in a type would require @MainActor isolation annotations
- **onKeyUp over onKeyDown:** Fires after user lifts keys, preventing the key-up event from being delivered to the overlay window
- **disable/enable on wake (not re-register):** Sleep/wake observer calls disable/enable only — re-calling onKeyUp would silently append a second handler, doubling calls on each keypress (research Pitfall 2)
- **fromHotkey refactor:** Rather than duplicating all three capture methods, added fromHotkey: Bool = false — hotkey path skips closePopover() and the 200ms popover-dismiss delay; delay is applied once in setupHotkeyMonitor closures
- **Silent conflict handling:** If another app holds the shortcut, KeyboardShortcuts handles gracefully without error

## Deviations from Plan

None - plan executed exactly as written. The fromHotkey refactor was explicitly offered as an option in the plan ("use your judgment"); chose it over duplicate methods because it's cleaner and avoids drift between code paths.
